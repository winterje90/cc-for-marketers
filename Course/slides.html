The Big Idea

What is Claude Code?

An AI assistant that lives inside your code editor. You describe what you want in plain English — it does the work.


It's not just for coding.
Claude Code can research, write, analyze data, manage files, automate workflows, and build things — all from the same place.
It's not ChatGPT.
Claude Code doesn't just answer questions. It reads your files, creates new ones, runs commands, and builds real things on your computer.

The Key Reframe

You're not learning to code

You're learning to direct an AI that does the work for you.


Your job:
  • Know what you want
  • Describe it clearly
  • Review the output
  • Give feedback
Claude Code's job:
  • Write the code
  • Create and edit files
  • Run commands
  • Fix its own mistakes
Think of it like managing a very fast, very literal junior team member. You provide direction. They do the execution.

Module 02

Your New Workspace

VS Code, the terminal & files

What Is VS Code?

Think of it like Microsoft Word, but for projects instead of documents.

  • Free, made by Microsoft
  • VS Code ≠ Visual Studio (different product!)
  • The place where you and Claude Code work together

The 4 Areas That Matter

  1. Sidebar — your file explorer
  2. Editor — where files open
  3. Terminal — where Claude Code runs
  4. Command Palette — search for anything
You can toggle these panels open and closed. Don't worry about anything else for now.

Files, Folders & Projects

  • Same as your computer's file system — nothing new
  • "Opening a folder" = opening a project
  • Common file types: .html .css .js .md .json
⚠️ #1 beginner mistake: opening a single file instead of the whole project folder

The Terminal (Don't Panic)

  • What it is: a text conversation with your computer
  • Claude Code uses it — you don't need to learn commands
  • When you see $ or % it means "ready for input"
The one thing to memorize: Ctrl+C (or Cmd+C) to cancel/stop anything

Quick Setup Tips

Extensions to install:
  • Prettier (auto-formatting)
  • Live Server (preview sites)
  • GitLens (see Git history)
Settings to change:
  • Auto Save (critical for Claude Code!)
  • Font size to your preference
  • Pick a theme you like
  • Turn on Word Wrap
Auto Save matters because Claude Code reads files from disk — if you forget to save, it reads stale content.

Prompting Basics

How to give good instructions

Vague
"Make me a landing page"
Vague
"Analyze this data"
Vague
"Help me with emails"
Specific
"Create a landing page for our spring webinar. Headline: 'Master ABM in 30 Days.' Include a signup form and 3 speaker bios."
Specific
"Read the CSV in /data/leads.csv and tell me how many leads came from each source last quarter."

Prompting Tips

The cheat sheet

  • Be specific — include names, numbers, details, goals
  • Give context — "This is for a B2B SaaS audience" or "We're a Series A startup"
  • Reference files — "Look at the homepage in index.html" or "Use the data in report.csv"
  • State the format — "Give me a markdown table" or "Create an HTML page" or "Save it as a CSV"
  • Iterate, don't start over — "Make the headline bigger" beats re-explaining everything
You'll get better at this fast. The first prompt doesn't need to be perfect — that's what the loop is for.

The Iteration Loop

Refining is the real skill

Your first result won't be perfect. That's expected. Here's how to refine:


Round 1
"Create a one-page summary of our Q1 marketing metrics from the spreadsheet in /data/"
Round 2
"Add a chart comparing MQLs by channel. Make the table sortable."
Round 3
"Change the color scheme to match our brand (navy #1B2A4A and teal #559AB3). Add our logo."
Each round builds on the last. You're not starting over — you're steering.

Module 04

Skills

Saved workflows you can reuse with one command

What Are Skills?

Slash commands for Claude Code

A skill is a set of instructions saved as a file. When you type /skill-name, Claude Code loads those instructions and follows them — like giving it a playbook.


Without a skill:
"Go to this company's website, pull their messaging, pricing, positioning, key features, and target audience into a structured competitive analysis doc using the format we used last time..."
With a skill:
/competitive-analysis https://competitor.com

Same result. One line instead of a paragraph. Repeatable by anyone on your team.

Why Skills Matter

Compound your best prompts

  • Consistency — same quality output every time, not dependent on how well you prompt that day
  • Speed — complex multi-step workflows triggered with one command
  • Shareability — anyone on your team can use the skill without writing the prompt themselves
  • Iteration — improve the skill once, everyone benefits
Think of skills like email templates — you write the perfect version once, then reuse and adapt it.

Examples for Marketers

Skills you might build

Research
  • /competitive-analysis
  • /seo-audit
  • /persona-builder
  • /content-strategy-audit
Content
  • /blog-post
  • /email-sequence
  • /social-posts
  • /case-study
Operations
  • /meeting-notes
  • /quarterly-report
  • /data-cleanup
  • /campaign-brief
You don't need to build these from scratch. Many already exist. Others are simple text files you can write yourself.

How Skills Work

It's just a text file

A skill is a markdown file (.md) saved in a specific folder. It contains instructions that Claude Code follows when you invoke it.


Where they live:
  • Project skills — in your project's .claude/ folder (shared with the team)
  • Personal skills — in your home ~/.claude/ folder (just for you)
  • Installable skills — downloaded from others, added in one step
The key insight:
If you can write a good prompt, you can write a skill. It's the same thing — just saved to a file so you don't have to type it again.

Module 05

Context OS

A knowledge system where AI never forgets what you've taught it

The Problem

Every AI session starts from scratch

  • You re-explain your business every time
  • You re-teach your preferences, your ICP, your voice
  • You re-provide the same context over and over
  • Knowledge doesn't compound — it resets
Imagine onboarding a new employee every single morning. That's what using AI without a context system feels like.

The Solution

A Context OS structures your knowledge so AI compounds it

Instead of scattered docs and repeated explanations, you build a structured knowledge base that Claude Code reads automatically every session.


Without Context OS:
  • Copy-paste context into every chat
  • Inconsistent outputs each time
  • Knowledge lives in your head
  • New team members start from zero
With Context OS:
  • AI reads your knowledge base automatically
  • Consistent, compounding outputs
  • Knowledge is captured and reusable
  • New team members onboard instantly

How It Works

Two layers of knowledge

Layer 1: Atomic Knowledge

Individual reusable concepts — your ICP, your positioning, your frameworks, product facts.

  • Each concept is its own file
  • Tagged and linked to related concepts
  • Lifecycle: emergent → validated → canonical
Layer 2: Operational Docs

Strategic documents that compose Layer 1 concepts — positioning docs, messaging guides, process playbooks.

  • Reference atomic concepts, don't redefine them
  • Synthesis docs summarize entire domains
  • Update once, everything downstream benefits
Layer 1 = individual Lego bricks. Layer 2 = the things you build with them. Change a brick and every build that uses it improves.

Module 06

GitHub 101

Saving, sharing & not losing your work

Git vs. GitHub

Git
  • Software on your computer
  • Tracks every change you make
Like "Track Changes" in Word
GitHub
  • Website that hosts your projects
  • Where you back up and collaborate
Like Google Drive for code

Why Version Control?

  • No more final_v2_FINAL.docx
  • Every change tracked — who, what, when
  • You can always go back
  • Multiple people can work without overwriting each other

The Core Concepts

Repository (repo)A project tracked by Git
CommitA labeled save point with a description
BranchA parallel draft of your project
MergeCombining a branch back into the main version
Push / PullUpload to / download from GitHub
CloneDownload a project from GitHub for the first time
Pull Request (PR)A proposal to merge changes, with review
A branch is like photocopying a document to try edits — if you like them, you merge the photocopy back in.

When Would a Marketer Use This?

  • Collaborating on website changes
  • Tracking content revisions
  • Reviewing and approving changes via PRs
  • Working with developers on the company site
  • Building a personal/team site via GitHub Pages
Claude Code handles the Git commands — you need the concepts to give good instructions.

Module 07

Key Concepts

Permissions, CLAUDE.md & web basics

The Permission System

  • Claude Code asks before it acts (edits files, runs commands)
  • Saying "no" is always safe
  • Almost everything is reversible (especially with Git)
  • You can pre-approve safe actions to skip future prompts
It's a safety feature, not an annoyance. Think of it as a colleague confirming before making changes.

Your Most Powerful Tool

The CLAUDE.md file

  • What: A briefing document that lives in your project folder
  • Why: The single most impactful thing you can write
  • What goes in it: project description, goals, preferences, things to avoid
It's just a text file — you already know how to write one. Think of it as onboarding a new team member every time a conversation starts.

HTML, CSS & JavaScript

You don't need to write these — just know what they do:

  • HTML = structure (the skeleton)
  • CSS = styling (the clothing)
  • JavaScript = behavior (the muscles)
Knowing this helps you give better prompts:

"Change the font" → CSS
"Add a new section" → HTML
"Make this button do something" → JS

Three Environments

Local vs. Remote vs. Live

LocalFiles on your computerWhere you + Claude Code work
RemoteFiles on GitHubWhere you back up & collaborate
DeployedA live websiteA separate step entirely
Changing one doesn't automatically change the others. Think of them as three different copies.

Packages & Dependencies

  • Modern projects use pre-built code (packages/libraries)
  • When Claude Code runs npm install, it's downloading these
  • node_modules = thousands of files — this is normal
  • package.json = the recipe; node_modules = the ingredients
Never edit node_modules directly

Module 08

Working Together

GitHub as your team's shared workspace

Why You Need This

Your work lives in files now

Landing pages, reports, Context OS docs, analysis — Claude Code creates real files. Without a system, you'll overwrite each other's changes and lose work.


Without GitHub:
  • "Which version is the latest?"
  • "Did you change this file too?"
  • "I think I lost my work"
With GitHub:
  • Every change tracked & labeled
  • Everyone works in parallel
  • Nothing is ever lost
Git is the "track changes" system. GitHub is the shared drive. Claude Code is the person clicking the buttons for you.

Saving Your Progress

Commits = labeled save points

A commit is a snapshot of your project at a moment in time, with a short description of what changed.


What you tell Claude Code
"Commit my changes with the message 'finished Q1 pipeline report'"

  • You can always go back to any previous commit — nothing is ever truly lost
  • Commit often — think of it like pressing save, but with a description
Like bookmarking a page in a notebook with a sticky note that says what's on that page.

Working in Parallel

Branches = your own copy to work on

A branch lets you make changes without affecting anyone else's work. The main branch is the source of truth.


Sarah is updating the messaging framework on her branch
Mike is building a new landing page on his branch
Alex is updating competitor profiles on his branch
  • Nobody blocks anyone else
  • Experiment freely — if it doesn't work, delete the branch
  • Merge back when you're done
What you tell Claude Code
"Create a new branch called 'q2-content-refresh'"
Like photocopying a document to try edits. If you like them, replace the original. If not, toss the photocopy.

Sharing & Syncing

Push, Pull & Clone

PushUpload your changes to GitHub"Share my work with the team"
PullDownload latest changes from GitHub"Get my teammate's updates"
CloneDownload the project for the first time"New team member getting set up"

Pull latest
→
Do your work
→
Commit
→
Push
If you forget to pull and someone changed the same file, Git flags a conflict. Claude Code can help you resolve it.

Reviewing Each Other's Work

Pull Requests = "review before we merge"

A Pull Request (PR) is a proposal: "I made changes on my branch — can someone review before it becomes official?"


  • Review a new competitor analysis before it enters the knowledge base
  • Check messaging updates before they go into the Context OS
  • Approve a landing page before it goes live
  • Comment, request changes, or approve — just like reviewing a Google Doc
What you tell Claude Code
"Create a pull request with the title 'Updated ICP profiles for Q2'"

Real Example

A marketing team's weekly workflow

DayWhoWhat happens

Nobody typed a single Git command. Claude Code did it all from plain English instructions.

What to tell Claude Code

You want to...Say this

Start something new safely"Create a new branch called '[name]'"

Things to Know

  • Don't put secrets in the repo — API keys and .env files belong in .gitignore
  • Commit messages matter — "updated stuff" is useless in 3 months. "Added Q1 pipeline model with channel breakdowns" is useful forever.
  • Pull before you push — avoids most conflicts
  • The main branch is sacred — always work on a branch and merge via PR
You can now save, share, collaborate, and recover — all through Claude Code in plain English.

Module 09

When Things Go Wrong

Recovery, confidence & common fears

Let's Address the Fear

"I see code and I'm scared"

  • You don't need to read the code — you review the output
  • If Claude Code built a page, look at the page, not the code behind it
  • If Claude Code wrote a summary, read the summary
  • The code is Claude's problem. The result is yours.
You don't need to understand how a car engine works to know whether it drove you to the right place.

Your Safety Net

Practical recovery options

What happenedWhat to do
Claude Code did something you didn't wantCmd+Z / Ctrl+Z to undo in the file
A file looks completely wrongTell Claude Code: "Undo your last change to [filename]"
Everything feels brokenStart a new Claude Code conversation — fresh context, fresh start
You want to go back to a known good stateIf using Git: Claude Code can revert to any previous commit
Something is running and won't stopCtrl+C in the terminal to cancel
Almost nothing is permanent. The whole system is designed to let you experiment safely.

Common Beginner Moments

This is all normal

  • "Claude Code is asking me to approve something I don't understand" — It's okay to say no. Ask Claude Code to explain what it wants to do first.
  • "There are thousands of files I didn't create" — That's node_modules. Totally normal. Ignore them.
  • "The terminal is showing a wall of text" — Claude Code is working. Let it finish. If stuck, Ctrl+C.
  • "I don't know if it worked" — Ask Claude Code: "Did that work? Show me the result."
